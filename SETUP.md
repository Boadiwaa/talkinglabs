# TalkingLabs — Setup Guide

This guide walks you through everything needed to build and run TalkingLabs on a physical device. An emulator/simulator is not recommended because `llama.rn` requires a real CPU (or Metal GPU on iOS) to load the model.

---

## Prerequisites

| Requirement | Version | Notes |
|-------------|---------|-------|
| Node.js | ≥ 18 | Check: `node --version` |
| npm | ≥ 9 | Comes with Node |
| Xcode | ≥ 15 | **macOS only** — required for iOS |
| Android Studio | ≥ Hedgehog | Required for Android |
| CocoaPods | ≥ 1.14 | `sudo gem install cocoapods` |
| Expo CLI | Latest | `npm install -g expo-cli` (optional) |
| Physical device | iOS 16+ or Android 10+ | llama.rn does not run on simulators |

---

## 1. Clone the Repository

```bash
git clone https://github.com/your-org/talkinglabs.git
cd talkinglabs
```

---

## 2. Install Dependencies

```bash
npm install
```

If you're on macOS and building for iOS, also install CocoaPods dependencies:

```bash
cd ios && pod install && cd ..
```

> **Note:** The `ios/` and `android/` folders are gitignored and will be regenerated by Expo's prebuild step. Run `npx expo prebuild` if they are missing.

---

## 3. Download the MedGemma Model Weights

The model files (~2–3 GB total) are **not included in the repository** (they are gitignored). You must download them separately.

### Step 3a — Get a Hugging Face access token

1. Create an account at [huggingface.co](https://huggingface.co)
2. Navigate to [google/medgemma-4b-it-gguf](https://huggingface.co/google/medgemma-4b-it-gguf) and request access
3. Once approved, generate a User Access Token at [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) (read access is sufficient)

### Step 3b — Run the download script

```bash
export HF_TOKEN=hf_your_token_here
chmod +x scripts/download-models.sh
./scripts/download-models.sh
```

This downloads two files into `models/`:

| File | Size | Purpose |
|------|------|---------|
| `medgemma-1.5-4b-it-Q3_K_M.gguf` | ~1.1 GB | Text inference model (lab extraction + interpretation) |
| `mmproj-F16.gguf` | ~550 MB | Multimodal projection weights (direct image analysis) |

### Alternative: Manual download

If the script fails, you can download the files manually from the Hugging Face model page and place them at:

```
models/medgemma-1.5-4b-it-Q3_K_M.gguf
models/mmproj-F16.gguf
```

## 4. Run on Device

### iOS (macOS required)

1. Connect your iPhone/iPad via USB and trust the computer.
2. Open Xcode, sign the app with your Apple Developer account:
   - Open `ios/TalkingLabs.xcworkspace`
   - Select the `TalkingLabs` target → Signing & Capabilities
   - Set your Team to your Apple ID (free account is fine for testing)
3. Close Xcode.
4. Build and run:

```bash
npx expo run:ios --device
```

Or use the Xcode Build button directly after the above command generates the project.

### Android

1. Enable Developer Options and USB Debugging on your Android device.
2. Connect via USB.
3. Push the model to the device (required before first run):

```bash
npm run android:push-model
```

This uses `adb push` to copy the model files to the device's storage. The app will auto-migrate them to its private documents directory on first launch.

4. Build and run:

```bash
npx expo run:android
```

> **Tip:** Run `npm run android:check-model` to verify the model was pushed correctly before launching.

---

## 5. First Launch

On first launch, the app will:

1. Detect the model file in its documents directory.
2. Load the model into memory (30–60 seconds on first load, faster subsequently).
3. Show a progress bar in `ModelStatusBar` while loading.
4. Once ready, the camera button in `LabUploadScreen` becomes active.

If the model fails to load, the app falls back to mock data and regex-based parsing so the UI remains functional.

---

## 6. Using the App (Demo Flow)

1. **Landing screen** → tap "Get Started".
2. **Register** with basic demographics (name, DOB, sex).
3. **Dashboard** → tap the upload button (bottom nav).
4. **Lab Upload** → choose "Take Photo" or "Upload from Gallery".
   - Point at a printed lab report.
   - The parsing pipeline runs automatically.
5. **Results** → tap any flagged result to see the full AI explanation.
6. **Listen** → tap the speaker icon to hear the explanation in your chosen language (English, French, Akan).
7. **Trends** → visit the Trends tab to see how a value has changed over multiple reports.

### Demo mode (no model required)

The Dashboard pre-loads 5 example patients from `src/data/mockData.js`. You can explore the full UI flow — charts, TTS, AI insight cards — without a model loaded. This is useful for quick evaluation on devices that cannot run the model.

## 7. EAS Build (for distributing to others)

To share a build with judges or testers without asking them to clone and build the repo:

### Setup EAS

```bash
npm install -g eas-cli
eas login
eas init   # Links the project to your Expo account
```

### Configure `eas.json`

Create `eas.json` in the project root:

```json
{
  "cli": {
    "version": ">= 10.0.0"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "ios": {
        "simulator": false
      }
    },
    "preview": {
      "distribution": "internal",
      "ios": {
        "buildConfiguration": "Release"
      }
    }
  }
}
```

### Build for internal testing

```bash
# iOS — creates a shareable .ipa via TestFlight or direct install link
eas build --platform ios --profile preview

# Android — creates a shareable .apk
eas build --platform android --profile preview
```

> **Important:** The model weights (~2–3 GB) are NOT included in the EAS build. The built app will download the model on first launch if `MODEL_DOWNLOAD_URL` is set in `src/services/LlamaService.js`. Without this, testers must use the mock data demo mode.

### Share the build

After the build completes on EAS servers:
- **iOS**: Distribute via TestFlight (add tester emails in App Store Connect) or share the install URL generated by EAS.
- **Android**: Share the `.apk` download link. Testers enable "Install unknown apps" on their device.

## 9. Troubleshooting

### "Model not found" on iOS

- Confirm `models/*.gguf` files exist locally.
- The Expo config plugin (`plugins/withModelAsset.js`) bundles the model into the native build. If you added the model files after the last native build, run `npx expo run:ios` again (not just `npm start`).

### App crashes immediately on Android

- Ensure the device has at least 4 GB RAM (the model needs ~2 GB to load).
- Try setting `n_gpu_layers: 0` and lowering `n_ctx` in `LlamaService.js` for low-memory devices.

### Model loads but inference hangs

- Check that no other app is running a large model simultaneously (limited RAM).
- Reduce `n_predict` in the LlamaService call for faster (shorter) responses.

### CocoaPods errors on `pod install`

```bash
cd ios && pod repo update && pod install && cd ..
```

### `expo-ocr` not found (autolinking)

- Confirm `app.json` has `"autolinking": { "nativeModulesDir": "./modules" }`.
- Run `npx expo prebuild --clean` to regenerate native folders.

---

## 10. Environment Notes

- The app does **not** require any `.env` file or API keys to run.
- The `HF_TOKEN` is only needed to download the model weights (step 3). It is not used at runtime.
- No backend server is required — all inference is on-device.
